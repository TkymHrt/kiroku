# ChatGPT本番接続・日次タスク

2026-10-21 JSTの記録。本番プラグイン「きろく」をOAuth/DCRで接続し、本人承認を受けて「きろくの日次要約」を登録した。接続先は `https://kiroku.tkymhrt.dpdns.org/mcp`。登録・復旧手順は [MCP運用](mcp-operations.md) を参照する。

## 日次設定

[日次タスクのチャット](https://chatgpt.com/c/6ad7eaba-6938-83e8-b378-b0d631f950ac)で毎日00:15、Asia/Tokyo、未処理最大3件を設定した。全文取得後に200〜400字程度の要約だけを保存し、currentの再生成・原文編集・外部URL取得は行わない。操作を固定して最大2回再送し、競合・認証・epoch・上限では停止する。成功/対象なしは静かに終了し、失敗だけ本文なしで通知する。

カードには「毎週0:15」と出る不一致があったが、一覧・編集画面・タイムゾーンは毎日00:15で一致した。後述の検証後に再開し、次回10月22日00:15の設定を確認した。この日次タスク自身の初回実行は記録時点で未確認。

実日記と重ならない1900-01-01に専用印付きの架空日記を作り、試験チャットの対象をその日付と印だけに限定した。実日記の原文送信は試験に含めていない。

旧チャットの拒否は再送せず、ツール宣言や認証を変えて回避していない。承認設定の変更でも解消しなかったため、元の「低リスクのツールを許可」へ戻した。

本人指示で作った [新規チャット](https://chatgpt.com/c/6ad7f2a5-2668-83ec-840c-2568cf2bdd96) には旧会話を引き継がず、手動MCP呼出・追加承認・権限変更を挟まずに無人保存が成功した。要約には予約後に追記した水やりが含まれ、原文にない事実を足していないことも確認した。成功理由や以前の拒否の根本原因は、この比較からは確定できない。

画面の予定08:05に対してD1保存は08:03:56だった。作成・追記後のバックグラウンド保存は成功したが、厳密に予定時刻以降の実行だったとは判定しない。画面の応答読込エラーも残るため、タスクの「完了」表示だけで保存成功と判断しない。

## 終了時の状態と証跡

各試験後、作成ID・本文・印を照合して通常APIでtrash→purgeした。要約・履歴の残存なし、実日記と既存receiptのdigest一致を確認し、本文を含まない検証receiptは無期限保持した。[検証JSON](mcp-production-chatgpt-proof.json)。

新規チャットの成功後に日次タスクを再開した。設定は毎日00:15、承認はデフォルト、検証用タスクは停止済み。これは10月21日の確認結果で、その後の実行成功を示すものではない。
