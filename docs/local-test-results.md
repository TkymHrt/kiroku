## Vite+移行の確認

開発・ビルド・単体・Lint・整形をVite+へ統一し、通常の単体設定とLint・整形設定を `vite.config.mts` へ集約した。Node単体テストではVoidの開発用プラグインを読み込まず、Workers連携は専用設定を使う。Vite+の型検査が、未importの一時ファイルへ意図的に入れたTS2322を終了コード1で拒否することも確認し、一時ファイルは削除した。frozen-lockfileでの再インストールは差分なし。開発サーバーをloopbackの5174番で起動し、画面・session API・faviconが200になることを確認して停止した。日記本文の取得・変更はしていない。

`build` はVoidの生成物を入力から除き、`dist/` だけを復元するキャッシュ付きタスクを標準利用する。Windowsの同一環境でキャッシュ付きタスクのコマンド全体を1回ずつ計測し、初回2.804秒、キャッシュ一致時0.381秒。`dist/` を退避して42ファイルすべての復元とSHA-256一致を確認した。`public/favicon.svg` の一時変更でcache missと配信物への反映を確認し、ソースを元に戻した。この測定はCIや別端末の所要時間を保証しない。

標準の `bun run build` でも入力変更時の通常ビルドと2回目のcache hitを確認した。`bun run build:fresh` は同じタスクを `--no-cache` で実行し、キャッシュを使わずビルドが成功した。

`check` 内のbuildも同じキャッシュを使う。強制再ビルドは `build:fresh`。静的検査・単体・Workers連携は毎回実行し、deployのbuildはVoidに任せる。CIのキャッシュ転送は追加していない。cf CLIの必須手順を除き、公開・Time TravelをVoid、SQL退避・分割復元を既存スクリプトへ整理した。後続の本番deploy・Access確認は[公開記録](deployment.md#2026-10-27の環境更新)を参照。リモートD1復旧は今回実行していない。
