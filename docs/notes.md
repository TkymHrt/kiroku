# 独立メモ

2026-10-28追加。日記とは別に、用件ごとに複数のMarkdownメモを作る。タイトルは200文字までの任意入力、本文は日記と同じ1,000,000 UTF-8 bytesまで。未入力タイトルは先頭の本文から表示名を作る。空の新規画面を開くだけではレコードを作らない。保存済みメモは空本文にできる。

## 画面と操作

PCでは左ナビの日記一覧とメモを主導線にし、日記のゴミ箱・設定を下側へ分ける。スマホは日記一覧・メモ・その他の3等分。その他に日記のゴミ箱・設定・ログアウトを置く。メモ画面上部のペンアイコン付き「メモを書く」から新規本文を編集する。作成ボタンに移動用の矢印は付けない。

メモ一覧は検索から始め、ナビと重複するページ見出しと総件数を画面に表示しない。読み上げ用の見出しは保持する。固定を先頭に、その中では更新日時・IDの降順。通常のメモも更新順。タイトル、短い抜粋、未完了件数、日本時間のYYYY/MM/DD形式の更新日を表示する。西暦は毎回含め、詳細の更新日も同じ形式とする。固定はピン、しまうは保管、削除はゴミ箱として別に保持する。チェック完了では自動移動・並び替え・削除しない。通常/しまったメモ/メモのゴミ箱を切り替えて検索できる。

新規メモは編集で、一覧から開く作成済みメモはプレビューで始める。前回の表示モードや以前のsessionStorageの値には依存しない。編集中も同じ画面で編集/プレビューを切り替えられる。プレビューのチェックは元のソース位置だけを変更し、重複文や他のMarkdownを保つ。チェック領域は44px。本文コピー・Markdown保存は現在の端末本文を使用し、タイトルを本文へ自動追加しない。

## データと同期

`notes` はクライアント発行UUIDをIDとし、タイトル・本文・固定・保管・論理削除・version・UTC作成更新時刻と一覧用の派生情報を持つ。`note_mutation_receipts` は本文なしの操作hash・結果version・epochを無期限保持する。GETはabsenceTokenを返す。作成は一度も使われていないIDだけに許可し、完全削除したIDを再利用しない。

`GET /api/notes/:id` は状態取得、`POST /api/notes/:id` はcreate/update/trash/restore/purge。タイトル・本文・固定・保管は同じversionで更新する。操作の固定hash、primary優先の前提照合、receipt INSERTと変更の同一batch、epoch照合を日記と同じ条件で実行する。

`POST /api/notes/query` は `{scope, query, cursor}` を受け、本文なしの一覧を最大30件返す。scopeはactive/archived/trash、検索語は100文字までのリテラル部分一致。検索語や本文をURLへ含めない。cursorは固定状態・更新日時・IDの組でページを継続する。

日記の既存ストアを維持し、メモにはIndexedDB `kiroku-note-drafts-v1` と独立BroadcastChannelを使う。`note-sync.ts` がメモの内容を内部の同期文書へ変換し、検証済み `DiarySyncEngine` の再送・lease・revision・version・epoch・競合解決を共用する。内部のbodyはタイトル・本文・固定・保管を持つJSON envelopeであり、Markdownエディター、外部API、JSON出力、Markdown退避には元の本文だけを渡す。サイズ上限はenvelopeではなく実本文に適用する。

認証切れ、競合、端末保存失敗では内容と退避操作を保持する。端末保存が完了しなければ画面移動・ログアウトを止める。競合は端末版/サーバー版のタイトル・本文・固定・保管状態を表示し、確認付き採用か手動統合を行う。

## 出力・検証範囲

JSON形式版3は日記とメモを同じsnapshotTokenで取得する。しまったメモ・ゴミ箱も含め、完全削除済みと端末だけの未同期変更は含めない。SQL復元試験はメモの約1MB本文・固定・保管・ゴミ箱・完全削除receiptを含めて比較する。

ローカルの単体・Workers連携・Edge E2Eで検証する。E2Eは予約日付/テスト用IDと架空本文だけを使う。Android実機、実Access期限切れ、メモの本番公開・実D1復元はこの変更のローカル検証に含まない。MCPと日次要約は日記のみを対象とする。

2026-10-28の最終版はLint・整形・型・単体128件・Workers連携7件・build、PC/390px Edge E2E全50件、ローカル復元self-testが成功。画面レビューのチェック項目の読み上げ名に関する指摘は、項目自身の表示文への関連付けで解消した。親項目の名前に子項目を混ぜず、重複項目と入れ子は元のソース位置で切り替える。

同日の作成ボタン・初期表示更新では、上部の「メモを書く」とペン1個の表示、新規の編集開始、編集で閉じた既存メモのプレビュー開始を確認した。check（単体128件・Workers7件・buildを含む）、メモ関連E2E8件、日記の作成・小画面ナビのE2E4件が成功。更新後の全50件は再実行していない。

続く一覧の見出し/総件数削除・年付き更新日の変更後も、checkとメモ関連E2E8件が成功。UTCの2025-12-31 14:59/15:00が日本時間では2025/12/31と2026/01/01になること、一覧の年表示と320pxでの日付の非改行・横はみ出し防止を確認した。この変更後も全50件は再実行していない。
