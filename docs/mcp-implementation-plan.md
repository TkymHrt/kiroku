# 日記MCP・日次要約 実装計画書

2026-10-20の計画。初期実装と本番公開は完了し、現行仕様は [要件](requirements.md)・[設計](architecture.md) に反映した。残る課題は [MCP検証](mcp-verification.md) で管理する。

## 実装した範囲

| 段階       | 成果物・参照先                                                                                |
| ---------- | --------------------------------------------------------------------------------------------- |
| 読取MCP    | 一覧・原文取得・日本語部分一致・未処理一覧。分割と上限は [設計](architecture.md#mcpと要約)    |
| 本人認証   | MCP専用Access/OAuth、既存画面の認証とCSRF維持。[公開記録](mcp-deployment.md)                  |
| 要約保存   | 本文と別表、独立revision、固定操作とreceipt、履歴、削除連動、復元/JSON更新                    |
| 日次処理   | 毎日00:15 JST、前日まで最大3件、事実だけを200〜400字程度へ要約。[登録手順](mcp-operations.md) |
| 検証・運用 | 自動検証、架空データの一時クラウド、ChatGPT予約保存、CPU/容量測定、復元と後片付け             |

本文の自動編集、FTS/embedding、任意SQL、要約UI、Cron/Workers AI、セルフホスト、追加課金、自動バックアップは追加していない。

## 残る受入項目

初回CPU最大20msが残り、Freeの10ms以内での安定運用は未合格。新規チャットの予約後の無人保存は成功したが、表示エラー、予定/保存時刻の不一致、日次タスク自身の初回実行は未確認。既存MVPのAndroid/Access/復旧後の端末確認も残る。

追加作業でも本文・未同期下書きの保持、固定mutationId/payload、version/epoch/absenceToken、primary優先照合、receiptと変更の同一batchを維持する。実データや本番DBを復元・負荷試験に使わず、課金や認証緩和で解決しない。
