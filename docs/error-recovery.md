# エラー表示と復旧導線（2026-10-18）

非エンジニアが、何に失敗したかと次にできる操作を同じ場所で理解できるようにした。ブラウザの`Failed to fetch`やAPIの例外文をそのまま表示しない。

| 状況                       | 案内・操作                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 初期接続失敗               | インターネット接続の確認と「もう一度接続する」                                                                             |
| 一覧読み込み失敗           | 「一覧を読み直す」。取得失敗を初回の空一覧として表示しない                                                                 |
| 日記読み込み失敗           | 「日記を読み直す」。本文を取得できていない状態を保存済み・記録なしと断定しない。端末の本文を表示する場合は最新未確認と案内 |
| サーバー保存失敗           | 本文が端末に残っていること、自動再試行、「保存を再試行」、本文コピー・Markdown保存                                         |
| 端末保存失敗・容量不足     | この画面を閉じるリスクを明示。先頭の本文コピー・Markdown保存で退避後、端末保存を再試行                                     |
| ログイン期限切れ           | ログイン画面を別タブで開き、元の画面で保存を再開                                                                           |
| 更新内容の衝突             | 両方の本文を確認し、採用または統合。生のAPIメッセージを表示しない                                                          |
| 一括出力失敗               | 「もう一度エクスポート」で出力処理そのものをやり直す                                                                       |
| 本文の上限超過・長期未同期 | 注意書きのそばから本文コピー・Markdown保存                                                                                 |

すべてのエラーには「エラー情報をコピー」を設けた。コピー対象はアプリ名・操作名・許可した分類コード・HTTP状態（取得できた場合）・コピー時刻・固定タイトルのみ。日記本文、URL、メール、認証情報、生のエラーメッセージやスタックは含めない。技術情報を画面で読まなくても、この情報を修正依頼へ貼り付けられる。

本文コピーとエラー情報コピーの成功通知・手動コピー画面を区別した。ブラウザが自動コピーを拒否した場合は、対象を読み取り専用の欄に表示し「すべて選択」から手動コピーできる。コピー結果を保存成功と扱わず、警告も消さない。

書き込みの保存・再送・競合判定とデータ構造は変更していない。手動の読み込み再試行は通常の通信失敗後の待ち時間を解除し、その場で読み直す。HTTPの`Retry-After`で待機を求められた場合は、その期限を維持してボタンを無効化し、待機理由を表示する。期限後にはボタンが自動で使えるようになる。再試行が競合や入力不正を上書きすることはない。

単体テスト86件、型チェックと本番ビルドが成功。PC・390px幅のブラウザ40ケースは段階実行で成功確認済み。失敗注入から再試行・本文退避・診断コピー・手動選択まで検証した。実行の内訳は[ローカル検証結果](local-test-results.md)に記録した。
